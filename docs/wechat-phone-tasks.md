# 用微信给自己的 iPhone 下任务（build 47）

在 Lan Agent 的「微信守候」里：

1. 把接收指令的**会话名**加入「只回复这些聊天」。私聊就在这里写对方的名字，例如「蓝海乐」；只填群名时不会读取你的私聊。
2. 把下指令的人写入「发言人白名单」。手机任务要求名字**完全相同**；白名单留空只能聊天，不能执行手机任务。
3. 开启「允许通过微信执行手机任务」，保持屏幕镜像并开始守候。群聊仍需要 @ 本账号或填写的口令；私聊不需要 @。
4. 在另一台设备的指定会话里发「打开备忘录，新建一条买牛奶的备忘录」。收到回执后，手机会调用与主页任务相同的执行器，完成后返回原会话回报。普通聊天照常回复。一次下一个任务，等上一条的结果回来再发下一条。

开关初始关闭。ChatTool 负责回复的模式不会执行跨 App 任务。会话范围与发言人必须同时在名单内；不要把微信显示名或 OCR 当作强身份认证。

执行失败会回报未完成。结果暂时发不出时，保存的是**回报文字**，只重试发送；连续三次仍失败会停止守候，再次开始可续发回报，不重做原任务。取消权限后不再发送待回报。停止按钮继续终止本次操作；停止期间不自动返回或发送，稍后开始守候才恢复允许的回报。

沿用现有隐私检查；受保护内容不会在回报中发送。付款、红包、转账、加好友、群管理和文件外发等限制继续保留。设备仍需连接小板、镜像正常、指针已校准、模型已配置。

本版本不改固件、Wi-Fi、配对或校准。IPA 未签名，需要用原来的签名安装方式更新；保留原 Bundle ID，避免丢失 App 配置。设备编译和模拟器测试不能代替真实 iPhone 上的点击、镜像与微信发送验收。

## build 46 速度调整

完成手机任务后立即开始回报，去掉原有约 6 秒排程冷却。画面检查从每 2 秒改为每 0.5 秒；持续变化仍需确认 2 秒。子任务结束接续从最多约 1 秒缩到约 0.1 秒；已在后台时跳过不可见的 0.8 秒出发动画。回报成功后正常冷却 6 秒，失败仍隔 20 秒再试。
这些数字来自代码中的固定等待；整体耗时仍受模型接口、镜像、任务步骤和微信页面影响，尚无真实 iPhone 的前后对比。日志新增 `watch timing` 的 read / decide / task run / fixed-plan run / check / report 阶段与毫秒耗时（check、report 包含子阶段，不能直接全部相加）。桌面只保留最新已验证版，交付新版后自动回收桌面旧版文件。
