# 小藍 iPad 版：移植計畫（2026-11-24）

## 目標
把安卓小藍（Echo，`E:\AIProjects\worktool-lan-watch`）的全部功能搬到 iPad：iPad 上一個叫「小藍」的 App，連小藍同一套自家伺服器、收同樣格式的指令、回報同樣格式的結果。對伺服器和後台來說，iPad 只是多一台小藍裝置。

## 為什麼不能直接把安卓程式搬過去
小藍是安卓 App（Java＋內嵌智微兔 DEX），靠安卓「無障礙服務」讀微信畫面、代點、代填字。iPadOS 不跑安卓程式，也不讓任何 App 讀別的 App 畫面或代點。所以 iPad 版是**照小藍的功能和指令重做一次**，操作方式換成大藍（Pilot）已經做好的「眼睛＋手」：
- 眼睛：iPad 螢幕鏡像（AirPlay）投到 ESP32-S3 板子，板子轉給 App；看圖辨識文字和按鈕。（iPhone 的「共享整個螢幕」要 iOS 27，iPad 是 17.4.1 不能用。）
- 手：ESP32-S3 藍牙滑鼠＋鍵盤（貝塞爾移動、真人節奏），打中文用大藍的輸入法。

## 架構
- 同一個 Xcode 專案（`ios/`）新增 App target「小藍」（獨立 bundle id，可和大藍並存），共用大藍的看畫面、點擊、打字、微信技能程式碼。
- iPad 原生（TARGETED_DEVICE_FAMILY 含 2）、最低 iOS 17。
- 伺服器用戶端：照小藍的企微（WeworkService）與個微（智微兔）兩條 WebSocket 協定，指令與回報欄位不改；測試期先連電腦上的模擬伺服器（18970／18971），使用者說「切回去」才連正式伺服器。

## 已知限制與風險
- 看畫面靠鏡像，比 iPhone 慢、畫質低；板子畫面設定要照 iPad 比例重調。
- iPad 版微信是左右兩欄，每個功能的位置和流程都要在 iPad 上重新認。
- 免費 Apple ID 簽名 7 天到期要重簽。
- 安卓上已有三支號在自動化後被登出／標記；iPad 雖是實體滑鼠點擊，仍有風險：只用測試號、只在测试群、看到安全提示立刻停。
- 新版本推上 GitHub 出版前都要使用者點頭。

## 技術設計（2026-11-25，看過大藍程式後）
- **可直接沿用**：
  - `Services/ChatToolLink.swift`：大藍已經是一台 ChatTool 機器人，連 `ws://<電腦>:8881/webserver/wechat/<機器人ID>`（就是 `chattool-wechat-robot/local-backend/server.py`），收 203「發訊息」並由「微信守候」打字送出，讀到的訊息也照機器人格式往上送。小藍 iPad 版的指令層從這裡擴充（206/207/219/501…）。
  - `Agent/`（看圖、指標、動作）、`Board/`（藍牙連板子、板子 Wi-Fi、AirPlay 鏡像收畫面）、小藍輸入法（`LanAgentKeyboard`）。
- **App 形式**：同一個 Xcode 專案加一個 target「小藍」（編譯旗標 `XIAOLAN`，同一套原始碼），iPad 原生（裝置家族含 2）、最低 iOS 17；首頁換成小藍的「伺服器／機器人 ID／板子／鏡像／指令記錄」畫面。輸入法擴充要用小藍自己的 bundle id，另做一個 keyboard target 共用原始碼。
- **語音**：照 `E:/AgentStorage/esp32/voice-board/docs/app-protocol.md` 用 CoreBluetooth 連語音板：任務開始送 `connect`，等 `headset link up` 再按住「按住說話」，一批發完送 `disconnect`。
- **第 0 步（先驗證地基，不寫程式）**：用已裝好的大藍 158 在 iPad 上確認三件事都通——①板子連上 iPad 同一個 Wi-Fi（大藍 設定 › Board Wi-Fi，Wi-Fi 密碼由使用者自己輸入）②iPad 控制中心「螢幕鏡像」投到板子、大藍收得到畫面 ③滑鼠在 iPad 上校正後點得準。這三件不通，小藍 iPad 版也做不成，所以先測。
