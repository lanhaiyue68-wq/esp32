## 三、本次決定：方案 E（Codex 提的），先不測、等板子

- 全無線：**電腦 —Wi-Fi→ 板子 —藍牙（假裝耳麥，HFP）→ iPhone 微信**。iPhone 能接的外部麥克風只有藍牙耳機、USB、有線，Wi-Fi 做不了麥克風。
- **板子由客戶在大陸買好寄來**（使用者沒管道買）：
  - 首選 **ESP32-WROVER-E 開發板**（多 8 MB PSRAM，整段錄音放得下）；次選 ESP32-WROOM-32E。
  - 必須是經典款「ESP32」：S3、C3、C6、H2 都沒有傳統藍牙，做不了耳麥（現在的滑鼠板就是 S3）。
  - 買 2 塊，一塊備用。
- **韌體要點**：
  - ESP-IDF 的 HFP Hands-Free（`hfp_hf` 範例），開 mSBC 16 kHz 寬頻（通話音質，微信語音夠用）。
  - 整段音訊先下載存進板子再送，因為 Wi-Fi 和藍牙共用天線，邊收邊送會斷斷續續。
  - 微信開始錄音時，iPhone 會打開到耳麥的通話音訊通道（SCO）；板子收到這個事件才開始送，開頭留一點空白；送完再讓 S3 滑鼠板放開「按住說話」。單條語音 ≤ 60 秒。
  - S3 繼續當滑鼠，新板子只管聲音；iPhone 同時連兩個藍牙裝置沒問題。
- **副作用與兩條規則**（使用者一開始以為只有按語音時才有影響；實際上只要藍牙連著，iPhone 就把板子當耳機，來電聲音會轉到板子）：
  1. 平時不連；電腦用 Wi-Fi 叫它「要發了」才用藍牙連上，一批發完自己斷開（一批一連，不要每條重連）。
  2. 連著時收到來電通知，立刻斷開，電話回到手機本身。
- **板子到之前可先做的驗證**（用手邊的藍牙耳機）：微信按住說話會不會用耳機麥克風（最關鍵）；耳機連著時來電聲音走哪；斷開後來電回到手機；連著時放音樂聲音在哪。
