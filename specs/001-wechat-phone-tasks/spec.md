# 微信作为手机任务入口

用户要求：接手 Claude 的「ESP32 网络配置与日志分析」，把微信收到的主人指令交给 Lan Agent 原有任务执行器，允许操作微信以外的 App，并把结果回到原会话。

## 使用场景与验收

1. 用户在守候设置开启「允许执行手机任务」，将自己的私聊名或群名列入会话范围，并填写发言人白名单。收到完全匹配的发言人指令「打开备忘录，新建一条买牛奶的备忘录」后，先回执，再调用现有执行器完成任务，最后回原会话报告实际结果。
2. 开关默认关闭。空白名单、名字仅部分匹配、未列出的会话、ChatTool 代答模式不能获得跨 App 执行权限；普通聊天仍走既有回复路径。
3. 不从历史、引用、知识库或普通参与者的文字生成新的主人任务。跨 App 执行使用本轮授权消息原文，模型仅决定是否需要执行。
4. 执行串行进行；返回结果不能使用离开微信前缓存的输入框坐标。停止后不能继续导航或发消息。
5. 执行结果若暂时未发出，保存待回报结果并重试发送，不重做原任务。启动守候可继续发出待回报结果；权限已取消时不发送。
6. 继续使用既有输入隐私检查、停止与连接检查；失败不能回报成功。不改动固件、网络、配对、校准、签名或模型凭据。

## 边界与交付

- 这仍是已启动守候、保持屏幕镜像的自用手机自动操作。微信显示名和截图 OCR 不能提供密码学身份认证；不要把名字白名单当成强身份验证。
- 不新增服务、账号接入或私信发送工具。App 内按用户设置回报任务结果属于产品功能，开发过程不主动发送真实微信消息。
- 在现有私有仓库的独立分支验证，交付 unsigned IPA 和来源校验；不合并主分支、不安装到手机、不刷固件。
- 完成标准：实际 Xcode 设备编译及模拟器 XCTest 通过，针对资格判断、原文传递、结果回报、停止与待回报重试有回归覆盖。真机的点击、镜像与微信发出仍需设备验收，不能以单测代替。
