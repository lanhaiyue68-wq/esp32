| 項目 | 決定 |
|---|---|

## 1. 總架構

```
 觸發：微信守候（主人訊息）／App 內手動下指令
                    │
           ┌────────▼────────┐
           │ 大腦：規劃者      │  一次把指令拆成多個子任務，標好先後與是否要用螢幕
           └────────┬────────┘
                    │
           ┌────────▼────────┐
           │ 排程器            │  一條「螢幕通道」（一次只能一個任務操作手機）
           │                  │  多條「思考通道」（不用螢幕的子任務同時進行）
           └───┬─────────┬────┘
               │         │
     ┌─────────▼───┐  ┌──▼─────────────┐
     │ 執行者（小腦）│  │ 思考子任務       │  擬回覆、整理、翻譯、摘要、算東西…
     │ 看→決定→做    │  │ 只呼叫模型，不碰螢幕│
     └─────┬───────┘  └────────────────┘
           │ 呼叫工具
  ┌────────┼──────────┬───────────┬────────────┬───────────┐
  眼        手          打字         開 App        記憶
 取屏＋     ESP32      Lan Agent    搜尋／記住     學會的按鈕、
 文字辨識   點/滑/按鍵   輸入法       圖示位置       路徑、App 位置
 →元素清單
```

## 2. 各部分怎麼做

### 2.1 大腦：規劃者 ＋ 執行者（兩層）
- **規劃者（強模型）**：收到「去開 8 點鬧鐘，再畫個太陽，回來給測試群發消息」，先拆成：①開鬧鐘（螢幕）②畫太陽（螢幕）③擬給測試群的話（思考）④發到測試群（螢幕，等③）。每個子任務有自己的步數上限，不再整個任務共用 40 步。
- **執行者（快模型）**：每一步看畫面、決定下一個或下幾個動作。一次可以回傳多個動作（例如「點搜尋→打字→點結果」），減少每點一下就問一次。
- **模型選擇**：規劃用強模型（GPT，透過 Plus；不行用豆包 Pro），執行用快的（豆包 lite 這類）。兩層都可以在設定裡換。

### 2.2 ChatGPT Plus 能不能用？（要先做可行性測試）
- 官方的 Codex 程式可以「用 ChatGPT 帳號登入」並用訂閱額度。我們在 App 裡做同樣的登入，**技術上可行，但不是 OpenAI 正式開放給第三方 App 的方式**，有被限制或改規則的風險。
- Plus 的 Codex 額度有上限（每幾小時有次數限制）。守候模式一小時可能要問模型上百次，**全部用 Plus 一定不夠**。所以設計成：Plus 只給「規劃者」用（次數少、要聰明），每一步的執行用豆包。
- 測試內容：在 App 裡登入 ChatGPT → 送一張截圖問一句 → 量回應時間、確認額度怎麼扣。不行就全部改用豆包，架構不變。

### 2.3 眼睛：共享整個螢幕 ＋ 元素清單
- 取屏照舊（直接取屏）。
- 新增：每張畫面先用 iPhone 本機文字辨識，整理成「元素清單」，例如 `[3] 發送 (908,543)`、`[7] 主人蓝海乐 (310,210)`，連同截圖一起給模型。
- 模型改成說「點 [3]」或「點『發送』」，程式從清單找到準確位置再叫 ESP32 去點。**有字的按鈕不再靠模型猜座標**。
- 沒字的圖示（箭頭、加號）：用「學會的按鈕」（記住樣子，下次照樣子找）。

### 2.4 手：ESP32
- 沿用現在的韌體、校準、點擊（已改成不晃游標）。
- 新增常用快捷：Home、返回（點左上角）、Enter 送出、搜尋（主畫面下拉）。

### 2.5 打字：Lan Agent 輸入法（自訂鍵盤）
- 和搜狗輸入法一樣是 iPhone 的「第三方鍵盤」。要打字時，Lan Agent 把文字交給輸入法，輸入法直接填進目前的輸入框。**取代「切 App 貼上」和「拼音一個字一個字打」**。
- 也能用在 Spotlight 搜尋：搜 App 名稱時不會再把「时钟」打成「始终」。
- 文字怎麼傳給輸入法：使用者用**全能簽**安裝。全能簽換成它的證書重簽，App Group（App 和輸入法共用的小空間）多半帶不過去，所以**直接走手機內部連線**：Lan Agent 在手機內開一個只給本機用的小服務（127.0.0.1），輸入法連過去拿「要打的字」，填完回報。Lan Agent 本來就靠背景音樂常駐，服務一直在。輸入法要開「允許完整取用」才能連線。
- 現有的靈動島擴充在全能簽下能正常運作（日誌有 Live Activity: started），所以「多一個擴充一起簽」這件事本身沒問題。
- 需要你在手機上做一次：設定 › 一般 › 鍵盤 › 新增「Lan Agent」，並打開「允許完整取用」。
- **先做最小測試版**，確認三件事：①開發板接著時 iPhone 還會顯示我們的鍵盤 ②App 在背景時能把文字交給它 ③填完按 Enter 微信會送出。三件都行才正式接上。

### 2.6 開 App：搜尋 ＋ 記住位置
- 第一次：Home → 下拉搜尋 → 用輸入法打 App 名稱 → 點結果。打開成功後，回想剛才在主畫面看到的那個圖示，記住它的樣子和所在頁。
- 之後：Home → 翻到那一頁 → 照樣子找到圖示直接點。找不到（被移走了）就退回搜尋，並更新記憶。
- 如果任務開始時 Lan Agent 還在前景，能用網址直接開的 App（微信、高德路線等）就直接開。

### 2.7 多任務並行（要先講清楚的限制）
- **手機只有一個螢幕、ESP32 只有一隻手**，兩個任務不能同時點螢幕。影片裡的「並行」也是：一個線程操作手機，另一個線程在寫程式（不碰螢幕）。
- 我們的做法：
  - **思考類子任務同時跑**：擬回覆、整理資料、翻譯、摘要、回答問題。
  - **螢幕類子任務排隊**，但可以穿插：A 任務在等 Claude 回覆時，先去做 B 任務的下一步，Claude 回好再切回來。
  - 每個子任務有自己的進度和結果，最後由規劃者統一回報。

### 2.8 微信守候
- 守候邏輯（檢查未讀、讀訊息、白名單、暗號、回報）保留，改成「觸發器＋回報器」：收到主人指令就交給大腦；任務完成由回報器用輸入法發回微信。
- 「收到」這類確認也用輸入法填，不再切 App。

### 2.9 記憶（學習）
- 保留：學會的按鈕、學會的路徑、經驗。
- 新增：App 圖示位置。
- 學習頁顯示每一類學會了幾個，可以清除。

## 3. 重寫 vs 重用

| 部分 | 處理 |
|---|---|
| ESP32 韌體、校準、點擊、滑動 | 重用 |
| 直接取屏、文字辨識、學會的按鈕／路徑 | 重用，文字辨識擴充成元素清單 |
| 微信守候的判斷（未讀、白名單、暗號、回報） | 重用，改成觸發器＋回報器 |
| 切 App 貼上、拼音逐字打 | 由輸入法取代（保留當備案） |
| 單一 AgentLoop（一個任務 40 步、每步問一次） | **重寫**成規劃者＋排程器＋執行者 |
| 保留不動的功能 | 捷徑/意圖、ChatTool＋知識庫、演示數據、Wi-Fi 鏡像（照你之前的要求） |

## 4. 分階段做，每階段都有固定驗收

| 階段 | 內容 | 驗收（你在手機上測） |
|---|---|---|
| A 可行性 | ①輸入法最小測試版 ②ChatGPT Plus 登入測試 | 輸入法三件事都行；Plus 能回應截圖並量到時間 |
| B 工具層 | 元素清單、輸入法打字、開 App（搜尋＋記位置） | 叫它打開 Claude 並輸入「你好」送出；第二次開 Claude 不用搜尋 |
| C 大腦 | 規劃者＋排程器＋執行者，接上微信守候 | 主人說「去 Claude 問一句話，把答案帶回來」，完整跑通 |
| D 並行 | 思考通道並行、螢幕任務穿插 | 「開鬧鐘＋擬一段測試群的話＋發出去」一次完成 |

每一階段：一兩件事、白話更新說明、交付前我先逐項自檢，再請你測固定情境。

## 5. 風險

- Plus 登入不是官方開放給第三方的方式，可能隨時失效 → 已設計豆包備案。
- 輸入法在「開發板當實體鍵盤」時能不能正常顯示，要實測 → 階段 A 先驗。
- 部分 App 可能禁止第三方鍵盤（密碼框一定禁止）→ 遇到時退回拼音／貼上。
- iPhone 每一步仍要截圖＋辨識，速度大約是影片安卓版的 2～3 倍時間。
